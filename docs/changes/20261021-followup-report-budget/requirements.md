# 资格跟进报告的实际输出上限

## 目标与范围

当前 `qualification-followup/v2` 声明最多 4 MiB 报告，但超限分支只删除六项检查的 `result`，两份完整输入快照仍可能超过上限。本变更只修复 Root 聚合报告的失败输出边界。

必须按最终 UTF-8 JSON 加一个 CLI 换行计算预算；普通未超限报告保持完整。超限时明确返回扫描错误、所有资格就绪为 false，保留六项实际退出码、已有 stdout/stderr 摘要和原输入身份。省略输入清单必须显式标记，不得伪称完整清单或重新验证过来源。

不增加费用、运行模型、现场数据、审核授权或新的资格。ADK 精确 pin、信任注册、审核日期、Native/G22/LTA/M5 门槛保持原义。

## 验收

- 真实默认 4 MiB 预算下，大输入闭包错误报告的最终 stdout 不超过上限。
- 正好上限、差一个换行字节和中文 UTF-8 字节数均有确定性测试。
- 输入清单摘要绑定省略前的 Git 身份、原快照 digest、条目数及已读取输入文件字节合计。
- 二级压缩诊断文本和 `source-before-invalid` 早返也受同一预算约束；实际出口码和既有失败原因保留。
- 内部常量若被测试替换为无法容纳最小六项诊断的值，明确报错，禁止输出截断或超限 JSON。
- 独立 Spec/Quality 审核和受保护 PR 验证必须检查实际最终 diff；源码修复不构成真实运行资格。
