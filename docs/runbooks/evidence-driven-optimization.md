# 以实际结果驱动优化

本说明复用现有 change、测试、effect campaign、review 和发布入口。适用于已发现重复工作、恢复缺陷、误判或性能瓶颈的变更。来源与本轮采纳边界见 `docs/changes/20261023-evidence-methods/`。

## 1. 冻结可比较的问题

先记录受影响调用者、精确 source、实际输入、可观察失败、正常对照和当前预算。区分四个结果：能力被路由、命令执行完成、最终产物正确、真实任务效果改善。前一项不能代替后一项。

代码缺陷用确定性反例关闭。真实 Agent 效果沿现有 effect preregistration/campaign/receipt 路径采集，不因本地测试通过就更新 G22、Native 或 Product M5。

## 2. 简化先找责任边界

先检索现有 owner 和调用点，再判断是否有重复状态、转发层或检查。一个模块应承担清楚的完整责任；文件数、行数和包装层数量不作为架构收益分数。

本轮优先收敛到已有 owner：路径身份由安装/输出边界处理，JSON 原子发布由 atomic_io 处理，进程资源由 process_budget 处理，版本和发布资产由 canonical release contract 处理。修改公共接口必须覆盖真实调用入口和异常路径。

## 3. 一次改变一个可解释因素

比较时固定任务集合、source、模型与版本、预算、环境、评分条件。可以逐项移除重复检查或 harness 组件，再观察质量与总成本；保留完整失败与重试分母。没有对照的优化只能报告观察结果。

不得把“反复尝试直到成功”当作高可靠性，也不得用短任务 helper 的毫秒级收益推断团队效率。

## 4. 验证实际工作与最终产物

基准必须确认预期工作确实执行、产物正确、输入非空，避免把 no-op、缓存误命中或错误快速返回当作加速。记录样本数、采样顺序、原始时长、冷/热条件和离散性。

至少根据问题选择以下实际指标：任务总完成时间、首次成功率、失败重试与恢复次数、重复验证耗时、人工介入分钟、最终缺陷数。runner-seconds、墙钟时长、Python tracemalloc 和进程 RSS 分开解释。未知 token、cost 或 outcome 保持缺失。

若已有可信同 snapshot 的验证回执可复用，沿既有 validation-plan 机制复用；输入不完整时禁用缓存。Git HEAD 不代表 Git index、工作树、环境和工具版本。

## 5. 从实际状态恢复

把准备、外部执行、结果确认、发布拆为现有可核对阶段。重试前读取实际当前状态，不能只相信上次内存状态或退出码。

对文件输出，发布前完成类型、别名、输入冲突和全输出准备检查。对多文件发布，明确补偿恢复协议；恢复失败保留原始材料。对远端提交、Release 或 API 的未知结果，先按精确标识读回，再决定补做，不能无条件重放副作用。

checkpoint 只能保存已记录状态；未确认的外部副作用不自动具备 exactly-once 语义。

## 6. 来源与升级边界

不可信日志、模型输出、外部文章和回执都是数据；结构化检查不能自行授予发布权限。来源、组件发布、runtime conformance 和产品资格由各自原权威判定。

第三方材料只作为方法输入。未审查许可证、供应链和平台假设前，不复制代码或安装资产包。已有能力优先增强；引入框架须有当前故障和可测收益依据。

2026-10-23 的时效结论：托管 OpenAI Evals/Agent Builder 退役仅构成当前选型限制；源码未发现活跃依赖。GitHub workflow dependency lockfiles 要求 Enterprise Cloud 且处公开预览，当前保留 full SHA pin 并观察。后续复审应重新核官方状态，不能沿用过期结论。

## 7. 关闭与复审

candidate/decision ledger 保留全部来源与选择；生产 adoption matrix 只投影符合现有生产 intake 合同的真实资产承接。单纯研究方法或选型观察留在 decision、implementation map 和 runbook，不因已写说明就登记生产 done。生产 adopt 必须具有 ADK/Codex 真实落点；observe intake 如需进入生产矩阵，仍须通过原 Agent/Skill/Workflow 深度、报告和退出条件检查。不得用尾注改变 done 的既有含义。

工程变更的关闭证据包括：原失败样例、修复后结果、正常控制、独立 Spec/Quality 审核、精确 SHA CI、实际发布/接入读回。没有执行的环节记录 not-run，不补造签名、测量或现场事件。

方法复审沿已有工作节奏进行，建议下一次变更或 2026-11-22 之前核对时效。若出现重复能力、无可验证增益、成本超约束或副作用不收敛，停止推广并按原 change 回退/退役。这个复审日期不是已创建的定时任务。
